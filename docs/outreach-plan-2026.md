## Rule (so days never stack over 100)

Each new person uses **3 slots**: today, today+3, today+10.

Before adding `N` new people on a day:

1. Today: follow-ups already due + `N` ≤ 100
2. Day +3: already reserved + `N` ≤ 100
3. Day +10: already reserved + `N` ≤ 100
4. This calendar month: emails ≤ 3,000

Then `N = min(room today, room +3, room +10, month room)`.

- Clean day (0 follow-ups, and +3/+10 are free) → up to **100** new
- Stacked day (follow-ups already booked) → only the leftover, often **0–15**
- Never add 30 or 100 on a day that already has ~85–100 follow-ups

1. Count follow-ups already due today (enrollments with `nextSendAt` today).
2. Compute `N` with the four-slot rule above.
3. Search + enrich `N` **new** people (skip existing email / Apollo id / any sent log).
4. Enroll and send step 1. Cron (or the worker) sends +3 and +10.
5. Optional: one preview to yourself — count it in the 100.

Do not start a second 100-person wave unless +3 and +10 still have room.
