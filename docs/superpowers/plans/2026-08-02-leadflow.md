# Leadflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a personal Next.js dashboard that imports Apollo leads with open filters, stores them in Postgres, exports CSV, and runs multi-step email sequences via Resend + Vercel Cron.

**Architecture:** Next.js App Router owns UI and API routes. Prisma talks to Postgres. Apollo and Resend are called only from the server. A cron route processes due enrollments in small batches. Single-user access is gated by an app-password session cookie.

**Tech Stack:** Next.js 15 (App Router), TypeScript, Prisma, Postgres, Vitest, Resend SDK, Apollo REST API (`x-api-key`), Vercel Cron

## Global Constraints

- Secrets (`APOLLO_API_KEY`, `RESEND_API_KEY`, `DATABASE_URL`, `APP_PASSWORD`, `CRON_SECRET`, `RESEND_FROM_EMAIL`) are server-only — never `NEXT_PUBLIC_`
- Dedupe imports by `email` first, else `apolloId`; skip people with no email and report counts
- Sequence merge fields: `{{firstName}}`, `{{lastName}}`, `{{company}}`, `{{title}}`
- Cron authenticates with `Authorization: Bearer ${CRON_SECRET}`
- Cron batch size: 25 enrollments per tick
- Transient send failures: one automatic retry (`attemptCount`); second failure marks enrollment `failed`
- Every outbound email includes an unsubscribe link
- No multi-user auth, SMS, LinkedIn, A/B tests, or industry preset packs in v1

- [ ] **Step 1: Implement session helpers**

Create `src/lib/auth.ts` using `jose` HS256 with secret = `APP_PASSWORD`:

```ts
import { SignJWT, jwtVerify } from "jose";

const COOKIE = "leadflow_session";
const encoder = new TextEncoder();

function secretKey() {
  const password = process.env.APP_PASSWORD;
  if (!password) throw new Error("APP_PASSWORD is not set");
  return encoder.encode(password);
}

export async function createSessionToken(): Promise<string> {
  return new SignJWT({ role: "operator" })
    .setProtectedHeader({ alg: "HS256" })
    .setIssuedAt()
    .setExpirationTime("30d")
    .sign(secretKey());
}

export async function verifySessionToken(token: string): Promise<boolean> {
  try {
    await jwtVerify(token, secretKey());
    return true;
  } catch {
    return false;
  }
}

export { COOKIE as SESSION_COOKIE };
```

```ts
export function leadsToCsv(
  leads: {
    firstName: string | null;
    lastName: string | null;
    email: string | null;
    title: string | null;
    company: string | null;
    industry: string | null;
    location: string | null;
    phone: string | null;
  }[],
): string {
  const header = [
    "firstName",
    "lastName",
    "email",
    "title",
    "company",
    "industry",
    "location",
    "phone",
  ];
  const escape = (v: string | null | undefined) => {
    const s = v ?? "";
    return `"${s.replaceAll('"', '""')}"`;
  };
  const lines = [
    header.join(","),
    ...leads.map((l) =>
      [
        l.firstName,
        l.lastName,
        l.email,
        l.title,
        l.company,
        l.industry,
        l.location,
        l.phone,
      ]
        .map(escape)
        .join(","),
    ),
  ];
  return lines.join("\n");
}
```

- [ ] **Step 1: Implement Resend wrapper**

```ts
import { Resend } from "resend";

export function getResend() {
  const key = process.env.RESEND_API_KEY;
  if (!key) throw new Error("RESEND_API_KEY is not set");
  return new Resend(key);
}

export async function sendCampaignEmail(opts: {
  to: string;
  subject: string;
  html: string;
}) {
  const resend = getResend();
  const from = process.env.RESEND_FROM_EMAIL;
  if (!from) throw new Error("RESEND_FROM_EMAIL is not set");
  const { data, error } = await resend.emails.send({
    from,
    to: opts.to,
    subject: opts.subject,
    html: opts.html,
  });
  if (error) {
    const err = new Error(error.message) as Error & { transient?: boolean };
    err.transient = false;
    throw err;
  }
  return { id: data?.id ?? "" };
}
```
